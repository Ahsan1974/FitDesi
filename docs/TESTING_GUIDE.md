# Testing

Backend, from `E:\FitDesi\backend` with `PYTHONPATH` set to that folder:

```powershell
.\.venv\Scripts\python -m pytest tests -q
```

- `tests/test_calc.py` covers the 250 kcal × 200 g = 500 kcal example, NULL nutrients, cooked weight differing from raw weight, Mifflin–St Jeor, the under-18 block, an aggressive date that is slowed down, step sources that are not summed, and an empty day that is not zero.
- `tests/test_api.py` covers registration, onboarding, search, portion math, diary idempotency, plan blocking, plan meals, weight, water, workouts, the health-source step choice, admin 403 versus admin access, a booking that stays unpaid, and a photo scan that does not invent foods.
- `tests/test_catalog.py` builds the full catalogue and expects at least 1000 foods, at least 1000 USDA rows, at least 200 calculated recipes, and a unique slug for Chicken Karahi whose cooked weight differs from its raw weight.

The API tests use an isolated in-memory SQLite database. They do not touch `fitdesi.db`.

Flutter:

```powershell
cd E:\FitDesi\mobile
E:\FitDesi\.tools\flutter\bin\flutter.bat analyze
E:\FitDesi\.tools\flutter\bin\flutter.bat test
```

The widget test checks that the signed-out screen shows FitDesi and Sign in. It does not drive a device, Health Connect, or the camera.

Alembic was autogenerated against an empty SQLite file. It was not applied on top of the already seeded `fitdesi.db`. On that file, stamp the revision instead of upgrading.
